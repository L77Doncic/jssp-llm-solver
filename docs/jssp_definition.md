# 静态作业车间调度问题（Job Shop Scheduling Problem, JSSP）定义

> 本文档为项目的基础定义文档。所有代码实现（数据结构、约束校验、makespan 计算）必须与此处形式化一致。

## 1. 问题形式化

### 1.1 实例（Instance）

一个 JSSP 实例由 **n 个工件**（jobs，记为 $J = \{1, \dots, n\}$）与 **m 台机器**（machines，记为 $M = \{1, \dots, m\}$）组成：

- 每个工件 $j$ 包含 **恰好 m 道工序**（经典 JSSP 中每道工序用不同的机器，即每工件恰好访问每台机器一次）；
- 工序 $O_{j,k}$ 表示工件 $j$ 的第 $k$ 道工序（$k = 1, \dots, m$）；
- 每道工序 $O_{j,k}$ 由二元组指定：
  - 加工机器：$\mu_{j,k} \in M$
  - 加工时间：$p_{j,k} > 0$（整数，**静态已知**，无随机性）

**静态性**：所有实例信息在调度开始前完全已知且不随时间变化（区别于动态调度中工件随机到达、机器故障等情形）。

### 1.2 决策变量

每道工序的开始时间 $s_{j,k} \ge 0$（连续或整数时间）。工序 $O_{j,k}$ 在 $[s_{j,k},\ s_{j,k} + p_{j,k})$ 内占用机器 $\mu_{j,k}$。

等价表示：每台机器上所有分配给它工序的**排列顺序**（排列一旦确定，最早开始时间可贪心推出）。

### 1.3 约束（三条硬约束）

1. **工序顺序约束（Job Precedence）**：同一工件的工序必须串行按序执行
   $$
   s_{j,k} + p_{j,k} \le s_{j,k+1}, \qquad \forall j \in J,\ k = 1, \dots, m-1
   $$

2. **机器独占约束（Machine Capacity / Disjunctive Constraint）**：同一台机器同一时刻最多加工一道工序
   $$
   \text{若 } \mu_{j,k} = \mu_{j',k'},\ \text{则 } s_{j,k} + p_{j,k} \le s_{j',k'} \ \ \text{或} \ \ s_{j',k'} + p_{j',k'} \le s_{j,k}
   $$

3. **不可抢占约束（Non-preemption）**：工序一旦开始必须连续加工完成，无插入、无中断。

### 1.4 优化目标

最小化 **makespan**（总完工时间，即最后完工工序的完成时刻）：

$$
\min\ C_{max} = \min_{s} \max_{j,k} \left( s_{j,k} + p_{j,k} \right)
$$

其他常见目标（本项目的备选/扩展）：总完工时间 $\sum C_j$、最大延迟 $L_{max}$、加权目标等。本项目主目标为 **makespan**。

### 1.5 可行解判定（验证器）

给定一组 $\{s_{j,k}\}$，检查：① 全部非负；② 每工件工序时间区间不重叠且顺序正确；③ 每机器上区间不重叠（可用按开始时间排序后扫描）。这将是 `src/evaluation/` 中可行性验证器的算法基础。

## 2. 复杂度与难度

- JSSP 是**强 NP-hard** 问题（Garey, Johnson & Sethi, 1976），且没有近似比为常数的多项式近似算法（除非 P=NP）。
- 实例极小也难：著名的 **ft10**（10×10）由 Fisher & Thompson 于 1963 年提出，其最优解（makespan=930）的证明经历了多年研究。
- 工业意义：调度直接影响产能、交期与资源利用率，是制造系统经典核心问题。

## 3. 标准公开实例与格式

### 3.1 常用基准集

| 系列 | 规模 | 说明 |
|------|------|------|
| ft06, ft10, ft20 | 6×6, 10×10, 20×5 | Fisher & Thompson，经典小实例（ft10 最优 930） |
| la01–la40 | 10×5 ~ 30×10 | Lawrence 系列，40 个实例，最常用的小中规模基准 |
| ta01–ta80 | 10×10 ~ 30×20 | Taillard 系列（ta01–ta80），大规模基准，80 个实例 |
| orb1–orb10 | 10×10 | Applegate & Cook |

### 3.2 文件格式（OR-Library / Taillard）

```
第一行：n m          （工件数 机器数）
随后 n 行，每行 2m 个整数（m 对）：
  (机器编号, 加工时间) (机器编号, 加工时间) ...   ← 机器编号通常从 1 或 0 开始
```

例如 ft06 前几行：`6 6` 然后每行 `2 1 0 3 1 6 3 7 5 3 4 6` 表示工件 1 的第一道工序在机器 2 上加工 1 单位时间，第二道在机器 0 上加工 3 单位……

**注意**：OR-Library 与 Taillard 的「机器编号 0/1 起点」与「(机器,时间)对 顺序」惯例需在解析器（`src/data/`）中统一并加测试。

### 3.3 解析器必须处理的两个惯例差异

1. OR-Library：每行先给出所有机器，再给出所有时间（两段式）；Taillard：每行直接是(机器,时间)对序列。
2. 机器编号从 0 还是 1 开始 → 解析后统一归一化为 0 起始。

## 4. 传统求解方法分类（作基线与监督信号来源）

| 类别 | 方法 | 本项目角色 |
|------|------|-----------|
| 精确算法 | 分支定界（B&B）、整数规划（disjunctive MILP）、CP | 小规模最优性验证 |
| 约束规划 | OR-Tools CP-SAT | **监督信号主来源**（中规模近似最优） |
| 启发式规则 | SPT、LPT、MWKR、MOR 等优先分配规则；Giffler-Thompson 算法 | 基线、LLM 输入特征 |
| 元启发式 | 遗传算法、禁忌搜索、模拟退火 | 大规模近似最优对照 |
| 学习方法 | 端到端神经网络（L2D 等）、LLM（本项目） | 本项目本体 |

## 5. 与本项目相关的问题变体（仅作区分）

- **流水车间调度（FSP/PFSP）**：所有工件走相同的机器顺序（LLMCoSolver 也覆盖了 PFSP）——不可与 JSSP 混淆，但可复用一个求解框架。
- **开放车间（OSP）**：工序无顺序约束。
- **动态 JSSP**：工件动态到达、随机加工时间等（本项目明确为**静态**，动态化是未来扩展）。
